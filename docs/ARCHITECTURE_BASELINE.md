# ASI 架构复位基线 v1.0

## 1. 产品定义

ASI（Agent / Skill Intelligence）是异构 Agent、Skill、MCP 和 Agent Framework 项目的透明纳管、运行态势感知与证据管理平台。它不创造新的 Skill 标准，不要求第三方项目迁移到 ASI 私有工作流规范。

## 2. 不可违反的原则

1. 原生优先：优先读取和调用项目自身声明的入口、运行时和控制规则。
2. 非侵入：默认只读，不修改第三方项目源文件和业务逻辑。
3. 不强制 DAG：DAG 只作为某些项目的可选展示，不作为统一执行模型。
4. 未知即未知：不确定入口、条件、依赖、分支、调用关系时必须标记未知。
5. 真实运行：不得用 sleep、固定返回值、硬编码节点结果冒充真实执行。
6. 证据分层：显式声明、静态推断、实际运行观察、重复验证必须分开标识。
7. 运行授权：第三方代码默认不执行；运行必须有明确入口、参数、权限、环境和用户确认。
8. 安全边界诚实：子进程、虚拟环境、容器不是同义词；没有真正隔离能力时不得标记“安全沙盒”。

## 3. 项目类型和纳管状态

- Native-described：项目具有原生配置或原生工作流描述。
- Parseable：可通过静态证据识别部分结构，但不代表完整控制流。
- Black-box runnable：内部控制流不透明，但入口和环境足以被确认，可作为黑盒纳管。
- Assisted extension：用户明确要求时，在原项目之外创建 ASI 扩展层。
- Indeterminate / blocked：入口、依赖、权限或环境未知，暂不能运行。

项目内部理解程度与项目运行能力是两个独立维度。

## 4. 证据等级

- L1 声明证据：项目配置、README、依赖清单、入口声明。
- L2 静态证据：AST、导入关系、函数调用等静态扫描结果。静态证据不能证明动态路径。
- L3 运行证据：某一次真实执行中观察到的进程、日志、事件、文件变化和退出状态。
- L4 重复验证：在明确记录的输入、依赖、环境和外部条件下重复测试。

不得将单次运行追踪描述为完整覆盖所有分支。

## 5. AI Studio 适配原则

- 默认技术栈：React 前端 + Node.js 服务端。
- 可使用 npm 依赖和服务端 Secrets；Firebase 可作为持久化选项，但必须实际启用并验证。
- 不假设宿主机存在 Python、Docker、系统包管理器或任意 CLI。
- 不假设 Cloud Run 本地文件系统是持久存储。
- 任意第三方项目代码执行默认关闭。需要执行时先探测运行时，再核实隔离、安全、授权和持久化能力。
- 平台不支持的功能应显示 BLOCKED / UNSUPPORTED，不允许用模拟数据补齐。

## 6. 当前 MVP 范围

本包实现 ZIP 静态导入与识别、项目元数据记录、运行时探测、审计 JSON 导出。它是后续真实运行适配器的基础，不宣称已经实现自动依赖安装、云端永久存储或安全执行。
