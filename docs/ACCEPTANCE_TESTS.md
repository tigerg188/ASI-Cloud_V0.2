# ASI MVP 验收清单

## A. 构建与基本运行
- [ ] `npm run check` 通过。
- [ ] `npm test` 通过。
- [ ] `npm run build` 通过。
- [ ] `npm start` 后 `/api/health` 返回 ok。
- [ ] 页面刷新后能重新从后端读取项目列表（仅证明当前存储介质可读，不代表云端持久化）。

## B. ZIP 导入
- [ ] 正常 ZIP 可导入。
- [ ] 非 ZIP 文件被拒绝。
- [ ] 超过 50MB 的上传被拒绝。
- [ ] 包含 `../`、绝对路径或异常路径的 ZIP 被拒绝。
- [ ] 文件数量超过 5000 被拒绝。
- [ ] 解压后累计大小超过 150MB 被拒绝。
- [ ] 重复导入产生独立项目记录，源文件 SHA-256 可追溯。

## C. 识别诚实性
- [ ] README、requirements.txt、pyproject.toml、package.json、SKILL.md 可被识别。
- [ ] 文件名入口只显示为“候选入口”，不得标记为真实入口。
- [ ] 纯 SKILL.md 不得显示为可独立运行程序。
- [ ] 未发现入口不得被解释为项目不可运行。
- [ ] 不得生成虚构 DAG 或虚构节点。

## D. 运行时边界
- [ ] 显示 Node/Python/Git 探测结果及版本。
- [ ] 明确提示宿主运行时可用不代表项目可运行。
- [ ] 默认不执行项目代码、不安装依赖。
- [ ] 不得显示伪造的执行进度、Token、节点状态或成功率。

## E. 数据与审计
- [ ] 审计 JSON 可以导出并可重新解析。
- [ ] 明确显示当前数据存储介质和持久性等级。
- [ ] 若使用本地文件存储，必须显示“托管环境重启后不保证保留”。
- [ ] 只有实际配置 Firestore/Cloud Storage 并通过重启、重新加载验证后，才能显示“云端持久化已验证”。

## F. 真实第三方项目验收（后续阶段，不属于当前静态 MVP）
- [ ] 选择真实开源仓库并记录 commit SHA、依赖版本、输入、环境变量和外部服务。
- [ ] 在 ASI 外部原生环境直接运行一次，保存基准证据。
- [ ] 在 ASI 受控运行环境运行同一项目，保存证据。
- [ ] 比较关键业务行为、实际入口、调用轨迹、产出物结构和退出状态。
- [ ] 不要求随机模型文本、时间戳或并发日志逐字节相同；要求事先定义可比较的业务不变量。
- [ ] 原生运行失败时，ASI 不得擅自修改逻辑将其包装成成功。
