# ASI Cloud · Google AI Studio Build Mode 主提示词

你正在一个全新的 Google AI Studio Build Mode 项目中，从本压缩包创建 ASI Cloud（Agent / Skill Intelligence Cloud）。不要继续或迁移此前存在问题的旧 ASI 项目；本包是本轮唯一代码基线。请先完整阅读本项目的 README.md、docs/ARCHITECTURE_BASELINE.md、docs/ACCEPTANCE_TESTS.md，不要跳过。

## 一、产品目标

ASI 是异构 Agent / Skill / MCP / Agent Framework 项目的透明纳管与运行态势感知平台。核心原则是：原生优先、非侵入、真实运行、证据驱动、未知即未知。

ASI 不重写第三方项目逻辑，不强制统一 DAG，不创造新的 Skill 标准。对无法解析的内部流程，允许以黑盒方式呈现；但必须区分“内部不透明”与“无法启动”。

## 二、严格适配 Google AI Studio

1. 使用 AI Studio Build Mode 实际支持的 Web 全栈结构：React 前端 + Node.js 服务端。
2. 不要默认假设运行容器具备 Python、Docker、apt、conda、任意系统命令或持久磁盘。
3. 先检测实际运行环境，再决定可实现的能力。没有证据的能力标记 UNSUPPORTED / BLOCKED。
4. 服务端 Secrets 不得传到前端，不得把 API Key 写入源码、项目包、日志或导出文件。
5. 若需要云端持久化，先确认 Firebase/Firestore 或 Cloud Storage 已真实启用，再实现并验证。不得把本地 JSON 文件冒充云端持久化。
6. 不要擅自启用任意第三方代码执行。ZIP 上传内容全部视为不可信数据。

## 三、必须遵守的架构边界

- 第三方项目原始源文件默认只读。
- 不把项目转换成 ASI 私有 DAG，不创建虚构节点。
- 不使用 `asyncio.sleep`、固定结果、硬编码样例或模拟处理器冒充执行。
- 入口识别结果必须标记为“候选”或“已由用户确认”，不能仅凭文件名宣称真实入口。
- 静态扫描、运行时观察、重复验证是不同证据等级。
- 一次运行的 trace 只代表本次实际发生的路径，不代表覆盖全部分支。
- UI 中每项功能必须对应真实后端逻辑；未实现的按钮应隐藏或明确禁用。

本阶段不需要调用 Gemini API，也不需要模型密钥。所有项目识别先使用可解释的确定性扫描规则；未来若增加 LLM 辅助说明，必须逐条引用真实文件证据，且不得让模型决定真实入口或执行命令。

## 四、第一阶段实现范围

先以当前代码包为基线完成以下事项：

1. 让 React + Node 项目能够在 AI Studio Build Mode 中正常预览和构建。
2. 保留现有简洁的 Google 风格浅色界面和导航结构，不要无理由重做 UI。
3. 实现 ZIP 上传、压缩包安全检查、项目清单识别、README/requirements/pyproject/package/SKILL 文件扫描。
4. 识别结果只提供证据和候选项，不宣称完整理解项目。
5. 显示宿主环境 Node/Python 等运行时探测结果，并明确说明这不等于项目可运行。
6. 保存项目识别记录并支持 JSON 审计导出。
7. 数据存储必须显示真实类型和持久性：本地文件、Firestore 或 Cloud Storage 不得混称。
8. 提供明确的“当前已实现 / 未实现 / 受平台限制”能力面板。

## 五、暂不实现

- 通用 DAG 引擎、DAG 自动转换、工作流重写和拖拽编辑器；
- 自动安装不可信项目依赖；
- 未经授权的任意代码执行；
- 多节点分布式 Worker；
- API Provider 通用拦截代理、Token 额度推测；
- 伪造的性能监控、进度百分比、模型配额或任务状态。

## 六、开发纪律

- 每次只完成一个阶段，不要一次性扩展全部功能。
- 修改前先列出将修改的文件和理由。
- 修改后运行可用的构建、类型检查和测试；若无法运行，必须说明原因。
- 输出真实测试结果，不允许虚构 PASS。
- 不得删除或大幅改变现有 UI、导航、已实现功能，除非先说明必要性并获得用户确认。
- 不得为了让预览成功而写入固定假数据。
- 任何失败都应保留原始错误和诊断信息，不要静默吞错。

## 七、首次响应要求

在开始改代码前，请先输出：
1. 你实际识别到的项目目录和关键文件；
2. 你确认 AI Studio 当前运行环境支持的能力，以及尚未确认的能力；
3. 当前代码中已实现、未实现、存在风险的功能清单；
4. 第一阶段准备修改的文件列表。

不要先写代码。等待用户确认后再开始第一阶段实施。
