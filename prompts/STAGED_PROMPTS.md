# ASI AI Studio 分阶段提示词

请一次只复制一阶段，不要连续提交全部阶段。

## 阶段 0：环境与代码审计（先执行）

请暂时不要修改任何代码。检查当前 AI Studio 项目结构、package.json、前后端入口、已安装依赖、启动方式和实际运行环境。逐项回答：
- 是否确实存在 Node 服务端？
- 是否存在 Python 解释器？若有，给出实际探测命令和版本输出；若没有，明确标记不支持。
- 是否能调用系统子进程？是否存在可靠隔离机制？不要把普通 child_process 说成沙盒。
- 本地文件在服务重启/重新部署后是否保留？用实际平台机制说明。
- Firestore / Cloud Storage 是否已启用并能读写？
- 当前代码哪些功能已真实实现，哪些只是 UI 或占位。

输出审计表和证据。不要猜测，不要改代码。

## 阶段 1：构建稳定性与基础功能

在用户确认审计结果后，修复当前项目使其可在 AI Studio Build Mode 正常运行。保留当前 UI 和目录结构。只修复构建、依赖、路由和 API 连通性问题。完成后提供构建结果、测试结果、修改文件清单和未解决问题。不要添加新功能。

## 阶段 2：导入与静态识别

实现 ZIP 导入和只读静态扫描。安全限制至少包括：文件大小、文件数量、压缩后总体积、路径穿越、异常路径、单文件大小。识别 README、requirements.txt、pyproject.toml、package.json、SKILL.md、MCP 配置等。入口只能列为候选，必须附证据文件和识别规则。不要执行 ZIP 中任何代码或安装脚本。无法识别时标记 UNKNOWN，不要让大模型编造拓扑。

## 阶段 3：持久化与审计

先说明 AI Studio 当前项目中可用的持久化服务。若 Firestore 已启用，设计并实现最小集合：projects、imports、audit_events。若项目文件或成果文件需要持久保存，再确认 Cloud Storage 是否可用。不要假设 Firestore 可以代替大文件对象存储。必须实现：浏览器刷新后可读取、服务重启后可读取、导出审计 JSON。完成后实际执行重启验证。没有完成重启验证，不得标记 CLOUD_PERSISTENCE_VERIFIED。

## 阶段 4：原生运行能力评估（不是立即开启执行）

评估 AI Studio/Cloud Run 实际能否安全运行第三方 Python/Node 项目。探测解释器、子进程、文件系统、网络、超时、资源限制、进程终止和隔离机制。对每个能力提供实际证据。若没有可靠隔离，明确标记 UNSAFE_FOR_UNTRUSTED_CODE。不要自动安装项目依赖，不要执行未知入口，不要开启任意命令执行。

## 阶段 5：受控真实运行适配器（只有满足前置条件才做）

只有在用户确认使用私有受控环境、运行时真实存在、权限边界和隔离机制已验证后，才实现运行适配器。运行命令必须以 executable + args 数组形式调用，禁止 shell 拼接。入口由用户确认，不得仅凭模型推断。每次运行记录项目版本/哈希、命令、参数、环境变量名称（不记录密钥值）、开始结束时间、stdout/stderr、退出码、文件变化和失败原因。停止/超时必须可用。若环境不支持，保留 BLOCKED 状态并停止，不得用模拟器替代。

## 阶段 6：真实项目验收

选择一个公开第三方 Agent/Skill 项目，固定 Git commit、依赖版本、输入和外部服务条件。先在项目原生环境直接运行，再在 ASI 纳管环境运行。比较关键业务行为、入口命令、调用事件、产物结构和退出状态。对非确定性模型输出，预先定义业务不变量，不要求随机文本或时间戳逐字节一致。报告必须包含失败、差异和证据；不得宣称完全一致而不提供对照数据。
